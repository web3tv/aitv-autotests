# Mailpit в контуре: перехват почты dev1 + dev2

В Mailpit переводим **оба стенда** — `api` (dev1) и `api2` (dev2), тесты гоняются на обоих.
Реальная доставка писем тогда проверяется только на проде.

Замеры с рабочего инстанса за месяц: RAM 42 МБ, CPU ~0%, база 9 МБ (лимит 5000 писем).

## Схема

- **Один** инстанс на оба стенда: workload `mailpit` в `devops/deploy/values-dev.yaml` — деплой и домен 3-го уровня создаются автоматически (ArgoCD + app-chart), kubectl/DNS не нужны. Письма стендов не мешают друг другу: тесты ищут по уникальным адресатам.
- Образ `axllent/mailpit:v1.30.7`; requests `50m/64Mi`, limits `500m/256Mi`; basic auth (`MP_UI_AUTH`) обязателен — в письмах коды верификации. Хранение в поде (без PVC): тесты читают письмо сразу после отправки, история не нужна.
- UI/API: `https://mailpit.web3tv.dev`, приватный ingress (только VPN — CI уже ходит через WireGuard).
- Оба api шлют напрямую: `MAILER_DSN=smtp://mailpit:1025` (внутрикластерный SMTP, TLS не нужен).

## Этапы

1. **PR в devops** *(Maxim, готов)* — блок `mailpit` в `deploy/values-dev.yaml`, merge → ArgoCD выкатит сам.
2. **SMTP-порт 1025** *(вопрос Роману)* — `service` у app-chart однопортовый (закрывает только UI 8025). Варианты:
   - **(а)** второй порт в service чарта (`extraPorts`?) — если чарт умеет или легко доучить;
   - **(б)** доп. Service на 5 строк — готов в `devops/mailpit/mailpit-smtp-service.yaml` (DSN тогда `smtp://mailpit-smtp:1025`).
3. **Переключить DSN** *(Роман, в Vault)* — `api#MAILER_DSN` и `api2#MAILER_DSN` → `smtp://mailpit:1025`, рестарт api/api2. Values-блоки api не трогаем.
4. **Автотесты** *(Maxim)* — два значения в `.env.web3tv`/`.env.web3tv2` (уже подготовлены), код не меняется. Прогон `@emails` + auth-сьютов на обоих стендах.
5. Через неделю стабильности выводим старую внешнюю схему чтения писем.

## Проверка и риски

- Проверка: под `mailpit` поднялся → UI открывается из VPN → регистрация на web3tv.dev и web3tv2.dev → письма с OTP в Mailpit → `@emails`-сьюты зелёные.
- **Вся** почта обоих стендов оседает в Mailpit — тестировщики смотрят коды в UI; реальная доставка проверяется только на проде.
- Prod не затрагивается. База ротируется сама (5000 писем).
- **Откат:** вернуть старые значения `MAILER_DSN` в Vault + рестарт — независимо по стендам.
